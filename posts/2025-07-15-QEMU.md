# QEMU Essentials: A Reference for System Emulation and Configuration

QEMU is the Queen of all Emus

## Introduction

It is technically an emulation or virtualization software that can emulate machines across different architectures[^qemu-a-proper-guide]. It offers arguably the **best performance** compared to other virtualization tools like VMware or VirtualBox. Personally, I've mostly used and preferred VMware to VirtualBox due to its smoother performance.

QEMU is unlike anything I've ever seen. To put it in perspective: **QEMU, emulating Debian with a full XFCE desktop, used _less_ memory than Microsoft Edge with just 20 tabs.** What is wrong with modern browser applications being so insanely memory-hungry?!

I was first introduced to QEMU while exploring RISC-V[^getting-familiar-with-riscv-and-wriitng-small-bootloader], but I didn't work with it seriously until watching Tsoding's recreational programming sessions[^time-to-learn-arm]. Later, at Accolade Electronics, I began working on Embedded Linux—this time diving deeper into QEMU, adding Buildroot and Yocto to my toolbelt as well.

I decided to write this blog (or more like a note to self) so I don't waste time setting everything up again next time, and maybe help someone else in the same situation[^emulating-aarch64-with-qemu-part1].

## Options

Here are some of the key QEMU command-line options I have used, along with quick reference. For the full detailed list checkout QEMU's documentations[^qemu-docs-invocation]. Gentoo Linux also has a useful reference page for QEMU options[^gentoo-linux-qemu-options]. 

> `-machine`

To select the emulated machine
`qemu-system-aarch64 -machine help` will give the list of supported machines. 

> `-cpu`

The CPU to emulate. `-cpu help` to see all options.

> `-accel`

For acceleration backend which can improve QEMU performance

options:
- `-accel tcg`  
	Use **Tiny Code Generator**, QEMU's default **software emulation** (slower, but works everywhere).
- `-accel kvm`  
	Use **KVM** (Kernel-based Virtual Machine) on Linux → **hardware-accelerated** (fast, needs host CPU + privileges).
- `-accel hvf`  
	Use **HVF** on macOS (Apple's Hypervisor.framework).
- `-accel whpx`  
	Use **WHPX** (Windows Hypervisor Platform) on Windows with AMD/Intel CPUs.

If you are on Windows, you will need to use either `tcg` or `whpx`.

````{admonition} WHPX Setting
:class: note

1. Enable `Windows Hypervisor Platform (WHPX)` or `Hyper-V Platform` from windows features.  [^install-hyper-v]
2. Run QEMU with:
	```console
	$ qemu-system-aarch64 -accel whpx
	```
3. If you encounter this error:
	```
	WHPX: setting APIC emulation mode in the hypervisor
	Windows Hypervisor Platform accelerator is operational 
	whpx: injection failed, MSI (0, 0) delivery: 0, dest_mode: 0, trigger mode: 0, vector: 0, lost (c0350005)
	```
4. Try[^whpx-acceleration-gh-issue]:
	```console
	$ qemu-system-aarch64 -accel whpx,kernel-irqchip=off
	```
````

> `-smp`

To configure number of virtual cpus (vCPUs) for virtual machine.  
I would suggest going through QEMU docs on `-smp`[^smp-invocation-qemu-documentation] before using this option.

| Term   | Meaning                                                                  |
| ------ | ------------------------------------------------------------------------ |
| Socket | A physical CPU package (e.g., a chip on motherboard).                    |
| Core   | An independent processing unit inside a socket.                          |
| Thread | A virtual execution unit inside a core (e.g., via Hyper-Threading).      |
| CPU    | In QEMU/KVM, a **vCPU** = 1 thread (what the guest sees as a processor). |


> `-m`

Sets the guest memory size. Example:
```
-m 2048  # 2 GB RAM
```


> `-bios`

QEMU uses `QEMU_EFI.fd` to boot UEFI-based guest OSes—especially for AArch64 (ARM 64-bit).

- Download from [Linaro Releases](https://releases.linaro.org/components/kernel/uefi-linaro/16.02/release/qemu64/)
- Bios files may also present in `"$QEMU_PATH/share/firmware/"`

[UEFI](https://en.wikipedia.org/wiki/UEFI) (Unified Extensible Firmware Interface) is the modern replacement for legacy BIOS.

![UEFI Booting](https://upload.wikimedia.org/wikipedia/commons/thumb/1/17/UEFI_boot_process.png/1920px-UEFI_boot_process.png)
<sup><sub>*Image Reference[^uefi-wikipedia]*</sub></sup>

`*.fd` = **UEFI Firmware Image**
- Simulates real UEFI firmware (which lives in flash ROM on real hardware)
- Loads before the OS kernel
- It runs before Linux, initializes hardware, and boots the kernel via bootloaders or direct EFI stubs.

> `-drive`

For virtual disk and how QEMU should treat it

```
-drive file=alpine.qcow2,format=qcow2,if=virtio
```
Defines a virtual storage device  
Booting a **pre-installed system**
- `file=alpine.qcow2` → your root filesystem
- `format=qcow2` → tells QEMU how to interpret the image format
- `if=virtio` → attaches the disk using fast `virtio` interface (used by modern OSes)
	Equivalent to
	```
	-drive file=alpine.qcow2,if=none,format=qcow2,id=hd0 \
	-device virtio-blk-device,drive=hd0
	```

This shows up in the guest as `/dev/vda` (virtio disk A). The kernel mounts it as root (`/`).


> `-hda`

Legacy shortcut for `-drive`

Instead of `-hda`, `-hdb`, `-hdc`, `-hdd`, you can use[^qemu-docs-invocation]:

```
qemu-system-x86_64 -drive file=file,index=0,media=disk
qemu-system-x86_64 -drive file=file,index=1,media=disk
qemu-system-x86_64 -drive file=file,index=2,media=disk
qemu-system-x86_64 -drive file=file,index=3,media=disk
```

> `-kernel`

Specifies the Linux kernel binary to boot 

 > `-initrd`

Provides an optional initramfs (compressed root filesystem in memory). Can be skipped if booting directly from disk.

> `console=ttyAMA0`

Required for serial output when using the `virt` machine on AArch64.

> `-device`

Used for adding virtual hardware
- `-device` explicitly tells QEMU **what virtual hardware to plug in**.
- need `-device` to **actually connect the drive** from `-drive` to the virtual hardware.

> `-cdrom`

- Used to mount ISO file as virtual CD-ROM
- Used when you want to boot **live OS** or **installer** (e.g. `alpine.iso`, `ubuntu.iso`).
	- Must pair with `-boot d` if you want to boot from it.
- not needed when booting kernel directly via `-kernel`, `initrd`
- Remove `-cdrom` later to boot installed system
- Equivalent to `-drive file="$ISO_PATH",media=cdrom`

> `-boot`

Specifies the boot order for drives  
like setting priority


| Option   | Use Case                                   | File Type             | Bootable? | Example                                     |
| -------- | ------------------------------------------ | --------------------- | --------- | ------------------------------------------- |
| `-cdrom` | Boot an **ISO image** (Live CD, installer) | `.iso`                | Yes       | `-cdrom alpine.iso`                         |
| `-drive` | Use any **disk image** (e.g. HDD/SSD)      | `.img`, `.qcow2`, etc | Yes       | `-drive file=disk.img,if=virtio,format=raw` |

| Method                | Use Case                                            | Bootloader Required | Root FS Required                        |
| --------------------- | --------------------------------------------------- | ------------------- | --------------------------------------- |
| `-bios` + `-drive`    | Boot **pre-installed OS** (e.g., Alpine in `qcow2`) | Yes (`UEFI`, etc.)  | Yes                                     |
| `-kernel` + `-initrd` | Boot directly from **Linux kernel + initramfs**     | No                  | Optional (initrd can be self-contained) |

> `-nic`

sets up networking for QEMU  
`-nic user` gives the guest internet access via NAT  
when you use `-nic`, you **should not** use `-device virtio-net-device` separately (to avoid duplicate NICs).

> `-netdev` 

low lever network backend configuration
`-netdev user,id=net0,hostfwd=tcp::2222-:22`
- user mode networking
- id=net0: ID reference to this backend
- hostfwd: port forwarding (host:2222->guest:22)
`-device virtio-net-device,netdev=net0` to connect frontend
So `-netdev` = _backend_, and `-device` = _frontend (NIC)_.

`-nic` is shortcut for simple setups. Combines `-netdev` + `-device` in one line.  
`-nic user,model=virtio` is equivalent to 
```
-netdev user,id=n0
-device virtio-net,netdev=n0
```

> `-rtc` 

For real time clock inside the guest VM.  
`base=utc`: Specify `base` as `utc` or `localtime` to let the RTC start at the current UTC or local time, respectively  
`clock=host`: sync the guest's RTC from the host system's clock. By default, the RTC is driven by the host system time.  

## Image Setup

### Creating Disk Image

QEMU supports many disk image formats, including growable disk images[^disk-images-qemu-documentation]. It supports different formats such as raw (`.img`), QEMU Copy-On-Write (`.qcow2`), 	Microsoft Virtual Hard Disk (`.vhdx`), etc.

```console
$ qemu-img create -f <format> <image_name> <size>
```

Example:
```console
$ qemu-img create -f qcow2 alpine.qcow2 16G
```

### Resizing Disk Image

You can also resize the disk
```console
$ qemu-img resize -f raw debian.img +32G
```

### Snapshots

```console
$ qemu-img snapshot [ -l | -a snapshot | -c snapshot | -d snapshot ] filename
```

The accepted arguments are as follows:
- `-l` lists all snapshots associated with the specified disk image.
- The apply option, `-a`, reverts the disk image (_filename_) to the state of a previously saved _snapshot_.
- `-c` creates a snapshot (_snapshot_) of an image (_filename_).
- `-d` deletes the specified snapshot.

Example: 
```console
$ qemu-img.exe snapshot -c debian-freshinstall debian.qcow2

$ qemu-img.exe snapshot -l debian.qcow2
Snapshot list:
ID      TAG               VM_SIZE                DATE        VM_CLOCK     ICOUNT
1       debian-freshinstall      0 B 2025-07-16 14:35:52  0000:00:00.000          0
```

You can also create an overlay snapshot image from base image[^create-snapshot-qemu].

Create a base image:
```console
$ qemu-img create -f qcow2 base.qcow2 10G
```

Create a snapshot image (overlay):

```console
$ qemu-img create -f qcow2 -b base.qcow2 overlay.qcow2
```

Boot from snapshot:

```console
$ qemu-system-x86_64 -drive file=overlay.qcow2,format=qcow2
```
Changes go to overlay.qcow2, base stays clean. Making any changes to its backing file (_base.qcow2_) will corrupt this snapshot image.

### Installing OS into Disk Image

```console
$ qemu-system-aarch64 \
    -bios QEMU_EFI.fd \
    -drive if=virtio,file=alpine.qcow2,format=qcow2 \
    -cdrom alpine.iso \
    -boot d
```
Or
```console
$ qemu-system-x86_64 \
    -hda debian.qcow2 \
    -cdrom debian.iso \
    -boot d
```

See option `-cdrom`.  
This boots from the provided ISO and installs OS to `disk_image.qcow2`. 

After installation
```console
$ qemu-system-x86_64 \
  -drive file=mydisk.qcow2,format=qcow2 \
  -boot c \
  -m 2G
```
this boots from the image like a virtual HDD. You'll require `-bios` options for AArch64 emulation.

## Emulating AArch64 (Alpine) on QEMU

![neofetch](/_static/images/blog_media/alpine-windows10.gif)

### Installing Alpine on QEMU

get the [alpine](https://alpinelinux.org/) ISO from [downloads | Alpine Linux](https://alpinelinux.org/downloads/)

Setup virtual machine type, bios, drive to boot from and for filesystem, etc. [^time-to-learn-arm][^running-aarch64-image-in-qemu]

```{code-block}
:caption: install.sh

ISO_PATH="alpine-standard-3.22.0-aarch64.iso"
QCOW2_IMAGE="alpine.qcow2"

qemu-img create -f qcow2 "$QCOW2_IMAGE" 16G

qemu-system-aarch64 \
    -M virt -cpu cortex-a53 -m 1G \
    -bios "$QEMU_PATH/share/edk2-aarch64-code.fd" \
    -drive if=virtio,file="$QCOW2_IMAGE",format=qcow2 \
    -device virtio-gpu \
    -cdrom "$ISO_PATH" \
    -boot d \
    -nographic \
    -nic user,model=virtio \
    -rtc base=utc,clock=host
```

Now, setup alpine:[^alpine-linux-qemu]

### Running Alpine (Headless)

```{code-block} console
:caption: run.sh

$ qemu-system-aarch64 \
    -M virt -cpu cortex-a53 -smp 4 -m 4G \
    -bios "$QEMU_PATH/share/edk2-aarch64-code.fd" \
    -drive if=virtio,file="$QCOW2_IMAGE",format=qcow2 \
    -nographic \
    -device virtio-gpu \
    -netdev user,id=mynet0,hostfwd=tcp::2222-:2222,hostfwd=tcp::6969-:22 \
    -device virtio-net-device,netdev=mynet0 \
    -rtc base=utc,clock=host

```

### Running Alpine (GUI/Desktop)

```{code-block} console
:caption: Alpine with XFCE Desktop Environment

$ qemu-system-aarch64 \
    -M virt -cpu cortex-a53 -smp 4 -m 4G \
    -bios "$QEMU_PATH/share/edk2-aarch64-code.fd" \
    -drive if=virtio,file="$QCOW2_IMAGE",format=qcow2 \
    -display sdl,gl=on \
    -device virtio-gpu \
    -device virtio-keyboard-pci \
    -device qemu-xhci \
    -device usb-tablet \
    -netdev user,id=mynet0,hostfwd=tcp::2222-:2222,hostfwd=tcp::6969-:22 \
    -device virtio-net-device,netdev=mynet0 \
    -nic user,model=virtio \
    -rtc base=utc,clock=host
```

## Emulating x86_64 (Debian) on QEMU

![neofetch](/_static/images/blog_media/debian-windows10.gif)

### Installing Debian on QEMU

get the [debian](https://www.debian.org/) ISO from [Downloading Debian USB/CD/DVD images via HTTP/FTP](https://www.debian.org/CD/http-ftp/#stable)

```{code-block} bash
:caption: install.sh

ISO_PATH="debian-12.11.0-amd64-netinst.iso"
QCOW2_IMAGE="debian.qcow2"

qemu-img create -f qcow2 "$QCOW2_IMAGE" 40G

qemu-system-x86_64 \
    -smp 8,cores=4,maxcpus=16 \
    -m 4G \
    -vga virtio \
    -display sdl,gl=on \
    -accel whpx,kernel-irqchip=off \
    -hda "$QCOW2_IMAGE" \
    -cdrom "$ISO_PATH" \
    -boot menu=on \
    -device qemu-xhci \
    -device usb-mouse \
    -device usb-kbd
```

`cpus` = `sockets` × `cores` × `threads`
that means I have
`8 = 2 sockets x 4 cores x 1 threads`
- threads = 1
- sockets = 2
- cores = 4

### Running Debian (GUI/Desktop)

```{code-block} console
:caption: run.sh

$ qemu-system-x86_64 \
    -smp 8,cores=4,maxcpus=16 \
    -accel whpx,kernel-irqchip=off \
    -m 4G \
    -vga virtio \
    -display sdl,gl=on \
    -drive file=debian.qcow2,format=qcow2,media=disk \
    -netdev user,id=mynet0,hostfwd=tcp::2223-:2223,hostfwd=tcp::6696-:22 \
    -device e1000,netdev=mynet0 \
    -rtc base=utc,clock=host \
    -device intel-hda \
    -device hda-duplex \
    -device qemu-xhci -device usb-mouse -device usb-kbd
```

For Audio: `-device intel-hda -device hda-duplex `

### Running Debian (Headless)

Using `-nographic` will work most of the time.

However, if you face errors such as being stuck in GRUB, it is likely due to GRUB expecting a graphical terminal.

```
SeaBIOS (version rel-1.16.3-0-ga6ed6b701f0a-prebuilt.qemu.org)
iPXE (http://ipxe.org) 00:03.0 CA00 PCI2.10 PnP PMM+BEFD0FF0+BEF30FF0 CA00
iPXE (http://ipxe.org) 00:04.0 CB00 PCI2.10 PnP PMM+BEF1FFF0 BEF30FF0 CB00

Booting from Hard Disk...
GRUB loading.
Welcome to GRUB!
```

To fix this, update GRUB settings to use serial terminal[^serial-console-howto]. 

Edit `/etc/default/grub` file, and make sure the following lines are present or uncommented.

```bash
GRUB_CMDLINE_LINUX="console=tty0 console=ttyS0,115200n8"
GRUB_TERMINAL=serial
GRUB_SERIAL_COMMAND="serial --speed=115200 --unit=0 --word=8 --parity=no --stop=1"
```
And update the grub.
```console
root@debian:~$ sudo update-grub
```

## Networking & SSH

### Port Forwarding

```
hostfwd=tcp::8080-:80  # Forward HTTP
hostfwd=udp::1234-:1234  # Forward UDP
```

Works only with `-netdev user` (user-mode networking).

Example:
```console
$ qemu-system-x86_64 \
  -m 1024 \
  -hda disk.img \
  -netdev user,id=net0,hostfwd=tcp::2222-:22 \
  -device e1000,netdev=net0
```

You can also  [forward multiple ports](https://gist.github.com/chrisvgt/7dc3e07c597ffcc1f5333d734213ab2c)

### SSH Setup

To check if ssh is working[^setting-ssh-server-alpine]

```console
root@debian:~$ sudo systemctl status sshd
root@debian:~$ sudo systemctl restart sshd
```
Or

```{code-block} console
root@pine:~$ rc status
root@pine:~$ rc-service sshd start 
```
Or
```console
root@pine:~$ ps aux | grep sshd
```

Or just do `ssh localhost`

The Guest machine is running ssh server which is listening on port 22 by default.
This must be forwarded to one of the Host (Windows)'s port.
To forward multiple ports:[^how-to-ssh-from-host-to-guest-using-qemu][^qemu-hostfwd-multiple-ports]
```console
$ qemu-system-aarch64 \
    ... \
    -netdev user,id=mynet0,hostfwd=tcp::2222-:2222,hostfwd=tcp::6969-:22 \
    -device virtio-net-device,netdev=mynet0 \
    ...
```

Also see [unix - How do I set up SSH so I don't have to type my password?](https://superuser.com/questions/8077/how-do-i-set-up-ssh-so-i-dont-have-to-type-my-password)[^setup-ssh-avoid-typing-password], to avoid having to type password each time. 

To use vim to edit over ssh
```bash
vim scp://root@localhost:6969//root/hello/hello.S
```

#### Troubleshooting

If you get permission denied even after having correct credentials you can check is the file `/etc/ssh/sshd_config` have the following lines.
```
PermitRootLogin yes
PasswordAuthentication yes
```
And restart the ssh service.

### X11 Forwarding

#### VcXsrv

Run [VcXsrv](https://sourceforge.net/projects/vcxsrv/) with "Disable access control" option  
or from command line
```console
$ vcxsrv.exe :0 -ac -multiwindow -clipboard -wgl -listen tcp
```

```console
root@pine:~$ xeyes 
connect localhost port 6010: Connection refused
Error: Can't open display: localhost:10.0
```
By default, VcXsrv listens on 6000 + display-number port

##### Why 6010 port?

X11 forwarding over SSH maps `DISPLAY=localhost:10.0` → **TCP port 6010**

if display is set to `localhost:10.0` try setting it to `localhost:0.0`

#### Install x11-apps

```console
root@debian:~$ sudo apt install x11-apps
```

Install xeyes and xauth

##### Alpine Troubleshooting

```console
root@pine:~$ apk add xeyes
ERROR: unable to select packages:
  xeyes (no such package):
    required by: world[xeyes]
```
Alpine's default installation is very minimal, and you might be missing the "community" repository, which contains desktop environment packages.

edit `/etc/apk/repositories` to add http://dl-cdn.alpinelinux.org/alpine/v3.22/community

```console
root@pine:~$ cat /etc/apk/repositories
#/media/vdb/apks
http://dl-cdn.alpinelinux.org/alpine/v3.22/main
http://dl-cdn.alpinelinux.org/alpine/v3.22/community

root@pine:~$ apk update
```

#### xauth

```
/usr/bin/xauth: file /root/.Xauthority does not exist
```
Generate `.Xauthority`:  
Run this in the **guest (Alpine)**:
```console
root@pine:~$ xauth generate :0 . trusted
```

> Or if you want to match SSH forwarding display:

```console
root@pine:~$ xauth generate localhost:10 . $(mcookie)
```

Verify with:
```console
root@pine:~$ xauth list
/unix:10  MIT-MAGIC-COOKIE-1  8b6797669a84fde1f6af7172589bcc6c
```

#### Complete Steps for X11 Forwarding

1. (Host) Start [VcXsrv](https://sourceforge.net/projects/vcxsrv/) with display no `10` instead of `-1` 
2. (Host) set display in environment `export DISPLAY=localhost:10.0`
3. (Guest) Edit `/etc/ssh/sshd_config` and add this line, if not present 
	```
	X11Forwarding yes
	```
	and restart ssh service
	```console
	root@pine:~$ /etc/init.d/sshd restart
	or
	root@pine:~$ rc-service sshd restart
	```
4. (Guest) Setup [xauth](#xauth) configuration.
5. (Host) connect with ssh[^how-to-ssh-from-host-to-guest-using-qemu]
	```console
	$ ssh root@localhost -p 6969 -XY
	# -Y (trusted) -X (untrusted)
	```

### SMB/CIFS

Create a shared folder on Windows. Follow [How to Setup SMB File Share on Windows Super Fast in 10 minutes](https://www.themakersphere.com/setup-smb-file-share-on-windows/) for complete steps.

Setup CIFS in Guest. Follow [Mount a Windows host's folder on a QEMU Linux guest](https://gist.github.com/neelabhg/8c6bfcdb44c0aa3f86bed00fe1f6da49) for complete steps.

On Host (Windows 10)
```
[Shared Folder Path]: D:\PROJECTS\QEMU_PROJECTS\debian\shared
    properties -> Sharing -> Share -> Select user -> (Administrator) Share
    (optional) set the folder permissions to "Everyone: Read/Write"
[Username]: ABD
```

On Guest (Linux Debian 6.1.0-37-amd64)
```console
root@debian:~$ ip route
default via 10.0.2.2 dev ens3
10.0.2.0/24 dev ens3 proto kernel scope link src 10.0.2.15
```
For Guest, the host's IP is `10.0.2.2`, which also default hardcoded when `-net nic -net user` is used.
```console
root@debian:~$ sudo apt install cifs-utils
root@debian:~$ sudo mount.cifs -o user=ABD,uid=1000,gid=1000 //10.0.2.2/shared /mnt
Password for ABD@//10.0.2.2/shared: 
root@debian:~$ ls /mnt
file_from_win.txt
```

> #### SMB
> - Stands for: **Server Message Block**
> - What it is:  
>     A network file sharing protocol developed by Microsoft.  
>     Allows file/folder/printer sharing between Windows and other systems over a network.
> - Used by: Windows, Samba (Linux), macOS
> - Ports: TCP 445 (modern), TCP 139 (older)
>
> #### CIFS
> - Stands for: **Common Internet File System**
> - What it is:  
>     An early version or dialect of SMB — specifically, SMBv1.  
>     Introduced by Microsoft in the 1990s.
> - Now deprecated: SMBv1 (CIFS) is considered insecure and slow, replaced by:
>     - SMBv2
>     - SMBv3
> 	
> In Linux, `mount.cifs` is the tool name, but it can connect to modern SMB (v2/v3) servers too.

## Others

### Debugging in QEMU

We can start QEMU in debug mode using the `-s` flag which opens a GDB server on TCP at port `1234`  
The `-S` is to prevent the CPU from starting immediately, so firmware/kernel is loaded but execution is halted at the reset vector.

```console
$ qemu-system-arm -machine stm32vldiscovery -nographic -kernel kernel.elf -s -S
```

and then start GDB instance to connect to QEMU

```console
$ gdb-multiarch kernel.elf -ex 'target remote localhost:1234'
```

For a different port use `-gdb tcp::5555` instead of `-s`.

### Kill QEMU

Incase of unresponsive behaviour use:
```console
$ ps | grep qemu | grep -v grep | awk '{print $1}' | xargs kill -9ps
```
